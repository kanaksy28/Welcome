## 1) To configure user

```
- git config --global user.name " "
```

## 2) Tracking file changes

```
- git init
- git add .
- git status
- git commit -m "Initial commit"
- git log
- git log --oneline
```

## 3) Uploading on GitHub

```
- git branch -M main
- git remote add origin "URL.git"
- git remote -v
- git push -u origin main
```

## 4) Cloning

```
- git clone "URL.git"
- cd REPO
- git add "."
- git commit -m "Update"
- git push
```

## 5) Create branches & merge them

```
- git branch
- git branch feature
- git switch -c feature

Make changes in the repo/file

- git add "."
- git commit -m "Adding new"
- git switch main
- git merge feature
- git log --oneline --graph --all
- git branch -d feature (delete feature)
- git push origin --delete feature

(Delete feature branch from remote copy if pushed)
```

## 6) Resolve a merge conflict

→ Can happen by creating on separate branch & performed

```
- echo "Og content" > demo.txt
- git add demo.txt
- git commit -m "commit"
- git branch -M main
- git switch -c feature

- echo "change-feature" > demo.txt
- git add demo.txt
- git commit -m ""

- git switch main
- echo "change-main"
- git add demo.txt
- git commit -m ""

- git merge feature

- git add demo.txt
- git commit -m "Resolved"
```

Important terminology for your viva
Workflow: An automated process defined in a YAML file inside .github/workflows/.
Event: An occurrence that triggers a workflow, such as a push, pull_request, or manual workflow_dispatch.
Job: A group of steps that run on a runner. Separate jobs can run in parallel or depend on one another.
Runner: The machine or environment that executes the workflow. For this practical, we will use ubuntu-latest.
Step: An individual task in a job, such as checking out code, running a shell command, or executing a test
Action: A reusable unit of automation used inside a workflow, such as actions/checkout to retrieve repository code.

Remember the hierarchy: Repository → Workflow → Job → Step → Command or Action.
A workflow is usually written in YAML, a human-readable configuration format.



Step 2: Create the workflow file
Open your repository on GitHub.
1. Click Add file → Create new file.
2. In the filename field, enter this exact path:
.github/workflows/hello.yml

The folders .github and workflows will be created automatically if they don't exist.
Step 3: Write the workflow code
Copy the following YAML into the file.


name: GitHub Actions Practical

on:
  push:
  workflow_dispatch:

jobs:
  demo:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v6

      - name: Display message
        run: echo "Hello! GitHub Actions is working."

      - name: Display event information
        run: |
          echo "Workflow triggered successfully."
          echo "Repository: $GITHUB_REPOSITORY"
          echo "Branch or ref: $GITHUB_REF"

      - name: List repository files
        run: ls -la



Step 4: Understand each part of the code
YAML section	Explanation
name	Sets the workflow's display name.
on: push	Triggers the workflow when code is pushed.
workflow_dispatch	Allows manual execution from GitHub's Actions interface.
jobs	Defines the jobs to run.
demo	The identifier for our job.
runs-on: ubuntu-latest	Requests a GitHub-hosted Ubuntu runner.
steps	Lists the tasks executed in order.
uses: actions/checkout@v6	Retrieves the repository code for the runner.
run: echo ...	Executes shell commands.
run: ls -la	Lists files in the checked-out repository, including hidden entries.


Step 5: Commit the workflow file
1. Scroll to the bottom of the GitHub file editor.
2. Enter a commit message such as Add GitHub Actions workflow.
3. Select the option to commit directly to main if available.
4. Click Commit changes.


Step 6: Execute the workflow
1. Open your GitHub repository.
2. Click the Actions tab.
3. Select GitHub Actions Practical from the workflow list.
4. Open the latest run.
5. Click the demo job to inspect its steps and logs.
